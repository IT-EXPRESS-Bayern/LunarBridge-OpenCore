# Externe Installation und Startauswahl

Geplant ist eine eigene GPT-Struktur auf der ausdrücklich ausgewählten externen Lexar-SSD. Ihre EFI-Systempartition soll `EFI/BOOT/BOOTx64.efi`, `EFI/OC/OpenCore.efi`, die qualifizierte Konfiguration und die einzeln bereitgestellten Hardwaretreiber tragen. Eine für Recovery ausreichend große FAT32-Partition trägt daneben `com.apple.recovery.boot/BaseSystem.dmg` und `BaseSystem.chunklist`. Die separate macOS-Zielpartition wird erst in einer tatsächlich erfolgreich gestarteten macOS-Umgebung als APFS eingerichtet.

Die bisherige Vorbereitung nennt 2 GiB FAT32 für EFI und Recovery. Das liegt über der Größe der bereits geladenen Recovery. Ein zusätzlicher USB-Stick ist für dieses geplante Layout nicht zwingend nötig, weil die externe SSD selbst das Startmedium sein soll. Dass Samsungs Firmware dieses konkrete USB-C-Gehäuse mit der gesicherten Bootkette annimmt und der macOS-USB-Treiber das Gerät weiter erreicht, bleibt zu prüfen. Die erste Anordnung wird bis zur bestätigten Datensicherung ausschließlich als Plan beschrieben; hier werden keine Partitionsbefehle ausgeführt.

Recovery ist eine kleine macOS-Installations- und Reparaturumgebung. Windows startet weder `BaseSystem.dmg` als Programm noch den macOS-Paketinstaller nativ. Das Abbild ist deshalb kein Ersatz für einen funktionsfähigen Bootpfad. Die Recovery benötigt anschließend Installationsdaten und eine erreichbare Netzwerkverbindung oder einen separat vollständig geprüften lokalen Installer. Auf diesem Gerät ist BE201-WLAN noch nicht als macOS-Netzwerkweg bestätigt. Der große Installer-Download wurde auf Wunsch abgebrochen und wird von diesem Modul nicht neu gestartet.

Bei einer späteren lokalen Vollinstaller-Lösung auf derselben SSD müssen die Recovery-/EFI- und Installer-Partitionen erhalten bleiben. Eine Anleitung, die das gesamte Installationsziel löscht, darf auf dieses Layout nicht unverändert angewendet werden. Das Grundschema für die Recovery ist im [OpenCore-Handbuch](https://github.com/acidanthera/OpenCorePkg/blob/6fe4d15cb66596d99d8cfedce69d8fc6dad71886/Docs/Configuration.tex) im Abschnitt zur Neuinstallation beschrieben; [Dortanias Windows-Vorbereitung](https://dortania.github.io/OpenCore-Install-Guide/installer-guide/windows-install.html) beschreibt das Verzeichnis und das Image-/Chunklist-Paar. Apples eigener [Weg für vollständige Installationsmedien](https://support.apple.com/en-us/101578) setzt einen gestarteten Mac beziehungsweise dessen macOS-Werkzeuge voraus.

Der vorgeschlagene Picker soll die interne Windows-EFI und die externe macOS-/Recovery-EFI sichtbar machen. Ein Windows-Start über OpenCore ist ein anderer Pfad als der bestehende direkte Windows Boot Manager. `Custom`-SMBIOS mit passendem GUID-Quirk reduziert OEM-SMBIOS-Konflikte; aktivierte ACPI-Patches können Windows trotzdem betreffen und bleiben deshalb separat zu prüfen. Der Generator schreibt keinen manuellen Windows-Gerätepfad und erzeugt keine Firmware-Bootoption.

Für den fertigen Betrieb sind Starts von Windows und macOS mit aktiver Firmware-Sicherheit zu belegen. Zusätzlich muss Windows ohne angeschlossene externe SSD über seinen erhaltenen Boot Manager funktionieren. Ob die Samsung-Firmware von einem bevorzugten externen Eintrag automatisch darauf zurückfällt oder die Firmware-Auswahl benötigt, ist unbekannt. Dieses Fallback-Verhalten lässt sich nicht durch einen erfolgreichen `ocvalidate`-Lauf nachweisen.
